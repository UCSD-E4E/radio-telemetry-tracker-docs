### Introduction

This project is dedicated to developing a state-of-the-art digital signal processing (DSP) and location estimation library, utilizing the time difference of arrival (TDOA) technique for position determination. The current solution for location estimation, available [here](https://github.com/UCSD-E4E/radio_collar_tracker_dsp2) depends on RSSI measurements from wildlife transmitters. By employing a least squares optimization approach to these measurements, the system produces a location estimate. However, due to the reliance on a drone for capturing varied power measurements with a single moving payload, a redesign is required to support multiple stationary towers.

### Objectives and Scope

The primary objective for this quarter is to develop the DSP software that will operate on individual towers, deferring the integration of the location estimation functionality. This software will process IQ data from a software defined radio (SDR) along with a timestamp marking the start of sampling, and then determine if a wildlife transmitter pulse event has occurred. If such an event is detected, the software will identify both the transmission frequency and the time at which the signal reached the SDR. Additionally, it may estimate the transmitter's power, assuming that all towers' SDRs are operating with the same gain setting.


### Hardware Considerations

Our hardware setup features the USRP B200 SDR, which offers an optional GPS Discipline Oscillator (GPDO). The software is intended to run on the UP 7000 microprocessor board, equipped with an N100 processor and 8GB of RAM.


### Field Considerations

Deploying this system in natural settings introduces challenges such as interference from vegetation and geological features. The goal is to achieve reliable detection of transmitter signals from distances of up to 500 meters.


### Software Development and Testing


Software development may be carried out on the microprocessor itself or within an Ubuntu virtual environment where the SDR is mounted as a device. While it is possible to simulate transmitter IQ data for testing purposes, no simulation framework has been developed yet. Instead, we have access to raw IQ data previously captured for similar tests (with the caveat that timestamps will need to be generated), and we also have wildlife transmitters available for both laboratory and field testing.
