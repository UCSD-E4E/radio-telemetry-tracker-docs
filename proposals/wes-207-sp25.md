# WES 207 SP25 Project

## Multi-Node Communication System for Wildlife Telemetry

[![GitHub](https://img.shields.io/badge/github-%23121011.svg?style=for-the-badge&logo=github&logoColor=white)](https://github.com/UCSD-E4E/radio-telemetry-tracker-tower-comms-package-2)

### Introduction

This project focuses on developing a communication system to enhance the Radio Telemetry Tracker's capabilities for monitoring small animals equipped with VHF wildlife transmitters. Departing from the previous one-to-one drone-to-GCS model, this initiative aims to establish a network where stationary towers communicate efficiently with a central server in a one-to-many (or many-to-many) configuration.

### Objectives and Scope

![image](/diagrams/img/tower-comms-flow.png)

The core objective is to create a robust, low-latency communication system that reliably transmits small data packets—approximately 100+ bytes per second—from each tower to a central server. The final deliverable will be a Python package, analogous to the existing [drone package](https://github.com/UCSD-E4E/radio-telemetry-tracker-drone-comms-package), allowing developers to register callback functions for processing incoming commands while abstracting the complexities of managing a multi-node network.

### Hardware Considerations

Each tower and the ground control station (GCS) will be built on Linux-based systems outfitted with chosen LoRa modules (or comparable communication hardware) and appropriate antennas (either directional or omnidirectional, based on performance needs). Although various power solutions (battery and solar) have been evaluated, the primary focus remains on minimizing power consumption for deployments in remote, wilderness settings.

### Field Considerations

Operating in natural environments introduces challenges such as signal interference from foliage and rocks. Towers will be placed 300–500 meters apart, with distances of up to 5–10 km from the GCS.

### Software Development and Testing

The software component will be developed as a Python package with functionalities to:
- Register callback functions for processing specific incoming commands.
- Generate and transmit data packets in a one-to-many communication framework.

Development will commence with simulated testing environments before transitioning to real-world field trials, likely near the trails behind Warren College. Key performance metrics will include packet loss rates and latency.

### Timeline, Budget, and Risk Assessment

The project is scheduled to run from April 5, 2025, to June 13, 2025, in conjunction with the WES class. Final timelines, budget details, and further risk assessments will be refined collaboratively with team input and Principal Investigators. Notable risks involve potential regulatory challenges related to radio transmissions (specifically concerning LoRa technology) and the technical complexities of ensuring reliable multi-node communication.
